# 개인정보 데이터맵과 출시 전 구현 과제

기준일: 2026-10-07. 저장소 코드·DDL을 기준으로 확인했다. 운영 대시보드의 전체 설정, 실제 사용자 프로필 내용, 외부 계약·로그·백업은 이번 검토에서 실사하지 않았다. 아래 “제안”은 현재 구현이나 확정한 보관 약속이 아니다.
계정 삭제 구현·검증은 2026-10-08 갱신했다. 전용 테스트 계정으로 실제 Supabase 연쇄 삭제를 확인했으며 기존 이용자 데이터는 변경하지 않았다.

| DB 백업·외부 사본 | 실제 주기 미확인 | 최대 잔존 기간과 접근 제한 확인. 복구 시 삭제 요청 재적용. 무기한 잔존을 허용하는 예외로 사용하지 않음 |

위 30일은 법정 기간도 현재 제품 약속도 아니다. 개인정보가 불필요해지면 파기하고, 법령에 따른 보존 대상은 분리해 관리해야 한다. 실제 적용 의무와 예외를 확인하여 기간을 확정한다. [제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334901).

## 4. 계정 삭제 구현 작업 명세

2026-10-08 `/account`의 탈퇴 링크, 공개 `/account/delete/`, 본인·최종 확인을 요구하는 삭제 API를 구현·운영 배포했다. 전용 계정으로 운영 API를 통해 Auth와 사용자 테이블 5개의 실제 삭제, 두 기기 토큰 차단을 검증했다. [구현·검증 기록](account-deletion.md). 실기기 동선·로그/백업 절차는 추가 확인 대상이다.

1. **진입과 설명**: 계정 화면에서 삭제 요청을 시작할 수 있게 한다. 삭제되는 계정·학습·저장·리워드 기록, 되돌릴 수 없음, 정당한 잔존 예외가 있다면 그 근거·기간을 보여준다.
2. **본인 확인**: 서버에서 인증 사용자를 확인하며, 클라이언트가 지정한 타인 ID를 받지 않는다. 최근 재인증이나 이에 준하는 확인을 정한다. 매직링크·Google 각각 지원한다.
3. **실제 삭제**: 서버 전용 권한으로 Auth 사용자 삭제와 `profiles` → `user_domain_levels`, `user_article_progress`, `daily_quota`, `ad_views` 연쇄 삭제를 검증한다. 공유 기사·퀴즈 자체는 회원 개인 데이터와 구분한다. 추가 테이블·로그·외부 사본을 함께 조사한다.
4. **진행 중 요청·세션**: 삭제 도중 채점·리워드 등이 새 개인 행을 만들지 않게 처리한다. 모든 기기의 세션/기존 토큰으로 재접근할 수 있는 기간과 차단 방법을 검증한다. 화면 이동만으로 삭제 성공을 판정하지 않는다.
5. **앱 밖의 요청 경로**: 앱 재설치 없이 열리는 웹 페이지에서 서비스·운영자, 요청 방법, 삭제 범위·기간·예외를 안내한다. 안전한 인증 또는 운영자가 처리 가능한 이메일 방식으로 요청을 접수한다. 실제 URL을 Play에 등록한다.
6. **실패·재시도**: 일부 삭제 실패를 성공으로 표시하지 않는다. 재요청이 안전하게 동작하고, 완료/지연 통지와 최소 처리 증빙 보관을 지원한다. 기존 사용자 데이터를 이용한 실험 대신 전용 테스트 계정으로 확인한다.
7. **운영 절차**: 로그·백업·제공사 사본에 대한 삭제 가능 범위와 최종 반영 시점을 확인하고, 복구 시 삭제 요청을 다시 적용한다. 적용되지 않는 “즉시 완전 삭제”를 약속하지 않는다.

검증 기준: 타인 계정 삭제 거부, 로그아웃 요청 거부, Google/이메일 계정 각각 삭제, 사용자 종속 행 잔존 여부, 기존 토큰·다른 기기 접근, 동시 채점·리워드, 중복 삭제·실패 재시도, 앱 밖 요청 완료, 공유 콘텐츠 보존. 삭제 구현 시 필요한 통합 테스트다.

Google Play는 계정 생성이 가능한 앱에 앱 내부 및 외부의 삭제 요청 경로를 요구한다. 로그아웃·비활성화는 계정 삭제를 대신하지 않는다. [계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko).

## 5. Play 데이터 보안 작성용 초벌 매핑

최종 제출 답변이 아니다. 최종 APK의 SDK·통신·제공사 로그를 확인한 뒤 콘솔의 당시 항목에 맞춘다. 아래는 우선 검토할 분류이며 용도에 따라 복수 항목이 적용될 수 있다.

| 데이터 | 검토할 Play 유형·목적 | 확인할 점 |
|---|---|---|
| 이메일·계정 ID | 개인정보: 이메일 주소·사용자 ID / 계정 관리·앱 기능 | 로그인 필수 기능이므로 모두 선택 수집이라고 기재하지 않음 |
| OAuth 이름·사진 | 개인정보의 이름 및 사진 관련 실제 수신 항목 | Auth 메타데이터·스코프를 확인하여 불필요 수집 축소 |
| 읽기·선택 분야·점수·답안·저장 | 앱 활동: 앱 상호작용·기타 사용자 생성 콘텐츠 등 / 앱 기능·맞춤설정 | 외부 저장되므로 “기기에만 보관” 아님; 퀴즈 답안의 실제 분류 확인 |
| 쿼터·리워드 요청 | 앱 활동 / 앱 기능·부정행위 방지 | 현재 광고사업자 전송 없이 시험 기록이 존재 |
| 접속 IP·UA·오류·인증 로그 | 실제 쓰임에 따른 기기/기타 ID·앱 정보/성능 등 | IP에서 위치를 추론하는지 등 실제 사용에 따라 분류; IP를 무조건 위치 수집으로 간주하지 않음 |
| 광고 ID·FCM 토큰 | 현재 관련 SDK 미연동 | 도입 후 실제 수집·공유·권한·동의와 방침을 함께 갱신 |

Play의 “공유” 예외에 해당하는 서비스 제공업체 전송인지와 한국법상 위탁·국외 이전 여부는 다른 판단이다. 계약상 역할을 확인하기 전에 “공유 없음”을 선택하지 않는다. 실제로 모든 대상 전송이 보호되는지 확인한 뒤 전송 중 암호화 항목에 답한다. [데이터 보안 안내](https://support.google.com/googleplay/android-developer/answer/10787469?hl=ko).

Android 원본 Manifest에는 INTERNET 권한과 `allowBackup="true"`가 있다. 최종 병합 Manifest와 세션 저장소의 백업 포함 여부를 확인해야 한다. 현재 선언만 보고 추후 SDK가 포함된 APK의 권한을 확정하지 않는다.
