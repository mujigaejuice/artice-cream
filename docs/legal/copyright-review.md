# 기사 가공·배포 저작권 1차 검토

확인일: 2026-10-07. 범위: 현재 코드, 활성 소스 40개 목록, 주요 5개 소스의 공개 약관/라이선스.
전체 발행처의 권리 승인을 완료한 문서는 아니다. 한국법을 우선 검토했으며 외국 발행처 약관의 준거법·계약 효력과 개별 글의 권리관계는 추가 판단 대상이다.

## 1. 결론과 근거

**현재의 “원문을 읽고 수준별 한국어 본문을 만들어 서비스하는 방식”을 일괄 허용할 근거는 확보되지 않았다.** 원문 링크, 재작성 고지, 원문 컬럼 접근 제한은 유용하지만 이용허락을 대신하지 않는다. 소스별 허용 범위가 확인될 때까지 권한 불명 콘텐츠의 공개 가공을 보류하는 방향을 권고한다. 현재 운영 설정이나 기존 콘텐츠는 이 문서 작업에서 변경하지 않았다.

단순 사실 전달에 해당하는 시사보도와 창작적 설명·구성·표현을 구분해야 한다. 기술 해설·칼럼·인터뷰·블로그 전체를 “뉴스”라는 이유로 보호 대상에서 제외할 수 없다. [저작권법 제7조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0007&lsiSeq=283335&urlMode=lsScJoRltInfoR).

원문 표현을 옮긴 번역·각색에는 2차적저작물 작성권 검토가 필요하다. 정당한 인용이나 공정이용을 주장하려면 목적, 사용량과 핵심성, 원문의 시장에 미치는 영향 등 실제 이용 형태를 봐야 한다. 교육용 기능, AI 사용, 특정 글자 수 또는 낮은 유사도만으로 허용 여부가 결정되지는 않는다. [제22조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0022&lsiSeq=283335&urlMode=lsScJoRltInfoR), [제28조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0028&lsiSeq=283335&urlMode=lsScJoRltInfoR), [제35조의5](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=05&joNo=0035&lsiSeq=283335&urlMode=lsScJoRltInfoR). 확인한 법령은 2026-08-11 시행본이다.

## 2. 실제 이용 흐름과 빈틈

| 단계 | 현재 구현 | 권리 검토·보완 |
|---|---|---|
| 발견·수집 | RSS 40개, 일부 과거 글 아카이브. 제목·요약을 LLM 분류에 이용 | RSS 공개나 robots 허용을 본문 재배포 허락으로 간주하지 않는다. 자동 수집·아카이브 범위를 따로 확인 |
| 원문 추출 | HTML 요청 후 Readability로 텍스트 추출; news는 12,000자까지, blog는 이를 넘으면 제외 | 길이 제한은 처리 비용 기준이다. 복제·추출의 권리 기준이 아니다 |
| 외부 처리 | 원문 제목·본문을 LLM 게이트웨이에 전송. 설정에 따라 Anthropic 경로도 존재 | 이용허락이 외부 처리·하위 제공사 전달을 포함하는지, 제공사 보관·학습 사용 여부 확인 |
| 저장 | `articles.original_text`, 원문 URL·제목·출처·이미지 URL, 가공본·용어·퀴즈 | 원문 미공개와 서버 보관 허용은 별도다. 목적 달성 후 원문 삭제 주기 필요 |
| 재작성 | 수준 3개, 목표 분량 500–800 / 900–1,400 / 1,300–2,000자(공백 제외); 용어 설명·퀴즈 생성 | 실제 산출물은 분량 목표를 넘을 수 있다. 원문 핵심 설명을 대체하는지 개별 표본 검토 |
| 제공 | 리더에 출처 호스트·원문 링크·재작성 문구 | 저자·원제·라이선스 링크·변경 내용·권리자 고지 보존이 부족. `author` 컬럼은 있지만 현재 수집 경로에서 채우지 않음 |
| 이미지 | `og:image` URL을 수집·저장. 현재 리더/카드의 이미지 표시 경로는 확인되지 않음 | 향후 표시·핫링크·복제 시 텍스트와 별도로 허락 확인. 출처 사이트로 이용자 IP 등이 전달되는 영향도 검토 |
| 만료·삭제 | 오래된 pending은 10일 후 `expired` 상태로 변경 | 실제 삭제가 아니다. 원문·가공본 자동 파기 및 권리 철회 대응 없음 |

## 4. 출시 통과 기준과 구현 과제

1. 소스와 개별 글에 권리 상태(`unreviewed`, `permitted`, `restricted`, `blocked`), 근거 URL/계약, 확인일, 허용 행위·기간을 기록한다. 법정 예외에 의존하는 경우에도 실제 이용 표본과 검토 근거를 남긴다.
2. 수집·가공·공개 단계마다 해당 행위가 허용되는지 확인한다. 피드 목록만 줄이면 이미 저장된 pending/ready 자료는 남으므로 기존 자료도 함께 분류한다.
3. 저자·원제·출처·라이선스와 변경 표시를 수집·노출하고 원문의 권리 고지를 보존한다. “기사/글을 한국어 학습용으로 재구성했으며 원 발행처의 승인·보증을 의미하지 않는다”는 문구도 허락을 대신하지 않는다.
4. 원문 보관기간과 LLM 제공사 전송 조건을 확정한다. 외부 입력 허락과 모델 학습 허락은 구별한다. 유사도 점검은 품질 검토 보조 수단으로만 사용한다.
5. 아래 신고·차단 절차를 구현·검증한 후 공개한다. 미확인 소스는 기능상 접근 가능하다는 이유로 승인하지 않는다.

**차단 구현상 주의:** [읽기 API](../../app/api/read/open/route.api.ts)는 현재 기사 `status`를 검사하지 않고, [RLS](../../supabase/policies.sql)는 인증 사용자의 가공본 읽기를 폭넓게 허용한다. 피드 제외나 `expired` 변경만으로 접근 차단을 보장할 수 없다. 직접 읽기·퀴즈·저장본·Supabase 조회와 캐시까지 같은 권리 상태를 적용해야 한다. 기사/가공본은 `user_article_progress` 및 `ad_views`와도 연결되어 있어 단순 삭제는 외래 키 제약에 걸릴 수 있다. 사용자 학습 기록에 남길 최소 정보와 삭제 순서를 먼저 정한다.

## 5. 권리자 문의·신고 대응안 — 아직 미구현

- 접수 창구: `[권리 문의 이메일 확정 필요]`. 요청할 정보는 권리자/대리인 연락처, 원문과 서비스 내 해당 글 URL, 문제된 이용, 권리 증빙의 최소 범위다.
- 운영자는 접수 후 해당 소스/기사의 추가 가공과 노출 중단 필요성을 우선 판단하고, 조사에 필요한 최소 증빙을 접근 제한하여 보관한다.
- 원문·가공본·용어·퀴즈·캐시와 외부 제공사 보관 사본을 조사한다. 권한 없는 이용이 확인되면 필요한 삭제·재발 방지·회신을 진행한다.
- 확인 전 임의로 상대 권리자의 허락을 추정하거나, 문구만 바꿔 재게시하지 않는다. 회신 기한·증빙 보관기간·담당자는 운영 정책으로 확정한다.

## 6. 발행처에 보낼 허락 요청 초안 — 발송하지 않음

제목: artice cream의 한국어 학습 콘텐츠 이용허락 문의

안녕하세요. `[운영자]`는 개발·AI 분야 글을 읽기 수준에 맞게 제공하는 artice cream을 준비하고 있습니다. `[대상 글/피드]`에 대해 아래 이용을 허락받고자 합니다.

1. RSS/웹에서 원문을 자동 수집하고 가공을 위해 서버에 `[기간]` 보관
2. `[실제 AI 제공사와 하위 처리업체]`에 원문을 보내 한국어 3개 수준의 읽기 본문·용어 설명·퀴즈 생성(제공사의 보관·학습 조건 별첨)
3. 생성 결과를 웹·Android에서 이용자에게 제공하고 광고로 수익화할 가능성
4. 원제·저자·출처·원문 링크·수정 사실과 요청하시는 권리 고지를 표시
5. `[대상 지역/언어/편수/이용기간]`, 과거 글 포함 여부, 이미지 제외 또는 별도 허락 범위

이용 가능 여부와 비용, 크레딧 방식, 원문/산출물 보관, 외부 AI 처리, 종료·철회 후 처리 조건을 알려주시면 그 범위에 맞추겠습니다. 예시 원문과 생성 결과는 `[검토 링크]`에서 확인하실 수 있습니다. 회신 전에는 이용허락을 받았다고 간주하지 않습니다.
